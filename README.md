# Sea Power · 海空战模拟平台

[在线游玩 · GitHub Pages](https://dns0129.github.io/Sea_Power/) · [源码仓库](https://github.com/dns0129/Sea_Power)

GitHub Pages 使用下方自动发布流程；首次发布需在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。之后推送 main 会先运行测试，再发布 dist/。不同域名的浏览器存档相互独立，可通过游戏内 JSON 导出／导入迁移。

原创海空联合战策略沙盘，提供 2D 战术海图与 3D 海面观察，参考 [Sea Power 的传感器、海空协同、实时暂停与时间压缩玩法](https://store.steampowered.com/app/1286220/)。包含真实海岸线上的历史单人任务与虚构海域沙盘；装备和胜负条件使用游戏平衡参数，不复用原游戏资源。

## 启动

macOS 双击 `启动海空战.command`，或运行 `npm start`。需要 Node.js 18 或以上，无须安装依赖。打开 http://127.0.0.1:8789；关闭终端或 Ctrl+C 停止服务。端口冲突时使用 `SEAPOWER_PORT=8790 npm start`。

源码在 `dist/`，无需构建。`server.mjs` 仅提供本机静态页面；Sites 使用 `.openai/hosting.json` 发布。

## 0.13.1 自由开火

所有单位的 2D／3D 指挥面板均提供“自由开火”按钮：开启后自动选择已发现且符合武器条件的目标，按射程、冷却和剩余弹药射击，无须逐次指定目标。框选多个单位后可一起切换，也可使用全队开关；保留航线与编组。关闭后保留独立的自动自卫。无适用武器或弹药时待命。开关随存档保存，任务计划和 AI 接管不会覆盖玩家设置。

## 0.13 双方扮演、二战自定义与海图风格

整合三个经典二战海战剧本、逐单位 AI、烟幕、缠斗和关键毁伤更新；新增剧本同样支持双方扮演与对应的任务结算。批量编队命令与逐单位接管共用指挥状态，手动航线优先。

- 所有剧本在开战前可选择扮演任一阵营，任务简报显示国旗、己方兵力、粗略敌情与任务／搜索海域。所选阵营拥有指挥权，历史任务的目标、增援和胜败按阵营对应；原蓝方由 AI 推进任务。AI 对战也可选“玩家指挥所选阵营”，或继续双方 AI 观战。开战后不能更换阵营，玩家视角不显示未侦察的敌方精确位置、装备和损伤。
- 二战高射炮可选择全部飞机、仅战斗机、仅鱼雷机或轰炸机与鱼雷机；手动射击和自动防空使用同一筛选规则，只按目视识别结果判断类别。驱逐舰与适用巡洋舰加入有限舰载直航鱼雷，按观测航向提前瞄准，发射后不追踪目标；空投鱼雷仍须进入低空。
- 新增加托级／伊号柴油潜艇，以及北卡罗来纳级／大和级战列舰。潜艇具有浮航、潜望镜与深潜状态、8 节潜航上限和有限电池；浮航充电并可用甲板炮，潜望镜深度可目视发射鱼雷，深潜不能开火或接收无线电。驱逐舰以低速声呐确认潜艇，在近距离投放有限深水炸弹。两型战列舰以重炮和高射炮作战，不配置鱼雷。
- 主页“二战海战 → 二战自定义海战”提供舰炮鱼雷、航母航空、驱逐舰与潜艇、空白部署四种预案，双方各 600 点，可增删本国二战舰机、调整天气和 AI 强度并保存继续。自定义模式没有强制时限与胜负，空白预案须先为双方部署战斗单位。
- 修正 3D 模型原点、舰首朝向、海拔和比例：2D 的海里坐标直接对应 3D 的 x/z，模型米制长度按 1852 米／海里换算。默认真实比例，可切换所有舰机统一放大 ×12；近景镜头、航迹和海浪尺寸同步调整。战列舰使用通用二战战列舰外形，潜艇使用按舰长／舰宽缩放的通用外形，并非精确复刻。
- “剧本细节”或战场“海图工具”可选择黑色夜航、白色航海图和蓝色深海三种主题；简报、海图及控制面板同步使用所选配色。主题和 3D 比例保存在浏览器偏好与战局文件中。v9 存档兼容 v1–v8，旧档默认蓝方、黑色海图、真实比例与全部飞机防空策略。

## 0.11 炮战、机群作战与三档 AI

- 舰炮命中率按基础精度 × 天气 × 目标可见度 × 测距仪 × 昼夜 × 距离计算；界面显示预计命中率、可见程度和测距仪完好度。晴朗、降雨、浓雾和风暴有不同影响，夜晚缩短目视距离。测距仪随舰体遭受命中而受损；已发射齐射保留发射时的精度。
- 二战飞机单位包含实际剩余数量：战斗／攻击小队初始六架，侦察小队三架。机枪／机炮比较机动、防御、火力与剩余飞机数；攻击机有有限自卫机枪。编组掩护提供有限协同收益，损失降低后续攻击火力；返航整备补充燃油和弹药，不恢复飞机或结构。整场战果会随这些损耗和指挥选择改变。
- 在 **2D 战术海图** 左键拖框多选，Shift／Ctrl／Command 点击加选；Alt 或中键拖动平移，触屏仍拖动平移。右键向选中单位下达航点，Shift 右键追加；速度、高度、待命、返航、自动交战也支持批量指令，无法执行的单位会给出原因。
- 单位面板可指定同方舰船护航、选择机群领队协同、独立行动或恢复作战计划。向编组领队下达航线后，僚机保持跟随；领队损失时解除跟随，低油返航优先。手动命令持续生效，不被中途岛自动作战计划覆盖。集中攻击只使用已确认的有效报告。
- **业余／专业／王牌** 分别以 24／8／4 秒作出指挥反应。业余偏重就近接敌；专业增加任务选择、护航与受损撤退；王牌进一步分配火力、分散搜索与多方向接敌。强度和进攻／防御等战术风格独立设置，双方不增加生命、弹药、命中或侦察信息。AI 对战可分别配置双方强度，战报与重赛保留设置。
- 任务简报的“剧本细节”和战场“剧本”组件可调整天气、昼夜与作战 AI 强度；3D 同步显示环境、剩余飞机和测距仪状态。AI 对战开始后配置锁定。v8 存档保存上述状态，兼容 v1–v7；旧存档默认白天、专业 AI 和完好的测距仪，飞机数量按剩余结构初始化。
## 0.12 逐单位 AI、目标跟随与关键毁伤

在 3D 单位详情或 2D 单位面板中，可以单独选择“AI 接管”“手动指挥”或“任务计划”。单独命令优先于全队计划；航母 AI 只调度本舰航空队，侦察机自行搜索，攻击单位依据本方报告接敌。可以从接触下拉框锁定并跟随敌方单位，也可以在 3D 点击敌方接触，由此前选中的友军执行锁定。固定岸基单位只跟踪和交战，不移动；AI 对战仍使用原有观察模式。

- 锁定目标后按收到的坐标、航向和速度追踪。失联后只前往最后报告，报告过期后等待重新发现，不跟踪隐藏的真实位置。指定目标优先于其他自动交战目标。
- 战斗机进入近距、同高度的有效接触后缠斗。二战缠斗距离为 1.8 海里、现代为 2.5 海里；攻击方航速限制为正常上限的 72%，被缠斗战斗机为 64%，其他被拦截机群为 72%。多个攻击者不会无限叠加减速，脱离后恢复原指令航速。
- 二战俯冲轰炸、鱼雷和舰炮降低命中率，关键部位命中可直接造成结构重伤。动力舱、水下舱室、飞行甲板、弹药库和舰桥／火控有独立记录；甲板重伤停止出动，舰桥重创暂时中断雷达和舰炮火控。小口径炮很难穿透战列舰装甲。轰炸小队调整为四个攻击批次，攻击计划为已发现的航母保留弹药。
- 二战舰队航母连续放飞间隔为 240 秒，护航航母为 300 秒；现代航母和两栖航空舰的原放飞间隔乘三。甲板在空容量、机库库存、重伤限制和整备补给继续生效。

3D 显示实际受限航速、缠斗状态和关键损伤。单位指挥、锁定、损伤和放飞准备均随战局保存；旧存档采用默认任务指挥。新增命令与近距战斗在 `dist/unit-orders.js`，关键毁伤在 `dist/ww2-damage.js`。

## 0.11 三个经典二战海战剧本

从主页选择“二战海战”，可进入中途岛及以下三个新剧本。每个剧本都有独立的战斗简介、史实背景与改编说明、部署海图和任务目标，敌方活动舰艇须侦察确认。

- **丹麦海峡，1941**：英军视角。胡德、威尔士亲王实施截击，巡洋舰外围跟踪；45 分钟内击伤俾斯麦并连续保持接触 120 秒，保住至少一艘可作战主力舰。
- **第二次瓜达尔卡纳尔海战，1942**：美军视角。华盛顿、南达科他与四艘驱逐舰夜间拦截日军炮击舰队；90 分钟内使雾岛失去战斗能力，机场完整度至少 60%，保住一艘可作战战列舰。
- **萨马岛，1944**：美军塔菲三号视角。六艘护航航母、三艘驱逐舰和四艘护航驱逐舰对抗日军中央舰队；用航空兵、烟幕与鱼雷反击掩护，90 分钟内撤出至少四艘护航航母。

新增大口径舰炮、装甲与齐射角度修正、水面舰直航鱼雷。夜间目视缩短，炮口焰短暂暴露位置；瓜岛两艘美军战列舰可以在本舰雷达连续跟踪后实施炮击，其余早期搜索雷达仍不能提供精确火控。烟幕对双方光学观察与射击生效，雷达可穿透烟幕。驱逐舰有有限烟幕库存、冷却和消散时间，支持在 3D 详情页和 2D 面板手动施放。

三个新剧本均有可选作战计划与手动指挥，指挥仅使用本方报告和已知任务地点。初始阵位、战斗窗口和航空小队为玩法改编，不强制史实沉没或撤退。新增原创通用战列舰 GLB 及可编辑 Blender 源文件；3D 夜景、烟幕、弹道和落水效果共用实际战局。存档保留烟幕、雷达跟踪、任务进度与撤离状态，旧战局继续兼容。

剧本资料与简化海岸在 `dist/ww2-scenarios.js`，任务和调度在 `dist/ww2-surface.js`，烟幕视线在 `dist/ww2-visibility.js`。战列舰仍使用通用年代原型，后续可替换为各级舰的独立模型。

## 0.10 二战海战 · 中途岛

主页新增独立“二战海战”模式，首个剧本为美军视角的 **中途岛海战**。进入前仍可逐页查看战斗简介、剧本细节、部署和任务目标；默认从 3D 海面进入，可随时切换战术海图。

- 三艘美军航母（企业、大黄蜂、约克城）对四艘日军航母（赤城、加贺、苍龙、飞龙），配套重巡洋舰、驱逐舰、中途岛基地和缩编航空小队。初始阵位、航空数量、武器批次、补给时间与四小时时限均为玩法改编；环礁使用简化示意轮廓。
- 目视搜索常开，PBY、舰载侦察机和水上侦察机负责搜索及持续跟踪。美军早期雷达用于空袭预警和概略搜索，低空探测受地平线限制，不会自动升级成精确火控航迹。无线电共享最后报告，失联报告保留最多十五分钟；实际攻击需要本单位目视确认。3D 在目视分类后显示对应通用年代外形，仍只使用报告位置，不展示敌方真实型号、损伤或装备。
- 采用舰炮齐射、高射炮、航空机枪／机炮、俯冲轰炸和低空直航鱼雷；不使用导弹、电子支援、现代数据链或自动化近防。鱼雷按观测航向超前瞄准，不在末段追踪隐藏目标。舰炮用于近距离海战；中途岛剧本主要依靠航空打击。
- “执行航空作战计划”协调搜索、舰队防空、攻击波护航和敌舰发现后的航空打击；也可分别下达搜索／防空／攻击波，或转为手动指挥。3D 的“装备”页及 2D 单位面板支持逐舰放飞。双方指挥只使用本方观测报告与公开搜索扇面。
- 航空队库存有限，起飞受甲板冷却和在空容量约束。小队返航后十分钟整备并消耗补给，航母结构低于 40% 时停止放飞。四小时内压制至少三艘日军航母，同时保住中途岛和至少一艘可作战美军航母即可获胜。
- 新增八类原创二战 GLB：直通甲板航母、重巡洋舰、驱逐舰、螺旋桨战斗机、俯冲轰炸机、鱼雷机、水上侦察机、航空基地。`ww2-fleet.blend` 保留可编辑源文件；外观是通用年代原型，不是各舰机的精确复刻。3D 展示可见弹道和命中／落水效果。

规则、单位与地图在 `dist/ww2-data.js`，剧本与调度在 `dist/ww2-missions.js`，建模脚本在 `scripts/build-ww2-models.py`。现有现代与历史战局继续使用原有规则，v1–v7 存档兼容；二战存档也保留航空库存、无线电报告、作战计划和返航整备。

## 0.9 3D 海面与通用模型

仍然从独立主页选择模式、剧本并阅读简报，进入战场后默认显示 3D 海面。点击舰船／战机模型或编队列表可拉近观察，在详情页查看状态、武器余量、舰载机与通用模型；支持旋转、平移、缩放、近景、跟随和编队全景。海面包含动态波浪、天空、日光与航迹，海岸使用当前剧本的地形。手机支持触屏旋转和双指缩放。

- 3D 与 2D 共用同一战局和选中单位。部署、挂载和战术指令通过“2D 战术海图”进入原有控制界面，海图顶部可返回 3D。3D 加载期间不推进模拟，WebGL 不可用或显示中断时回到可操作的海图。
- 制作 10 类原创通用资产，覆盖全部现有平台：航母、驱逐舰、护卫舰、补给舰、潜艇、战机、攻击机、预警机、直升机、岸基设施。模型与游戏性能独立，外观与飞行高度采用示意显示比例；深潜单位在海面作位置示意。
- 详情的“模型”页可下载当前 GLB 与整套 Blender 源文件。命名零件保留可编辑结构；[模型修改与导出说明](dist/assets/models/README.md) 提供替换方法。
- 手动战局和 AI 阵营视角遵守既有侦察信息。隐藏敌方不会传入 3D 场景；接触仅使用侦察坐标和已知信息，不反查真实单位。AI 全局观察可以显示双方。
- Three.js r169 和全部资产随页面本地加载，无外部渲染 CDN。首次进入战场才加载 3D 模块，不影响主页。静态资源无需构建；运行和测试仍不需要 npm 安装依赖。

## 0.8.2 独立主页入口与选择页对齐

默认入口转到独立的 `home.html` 主菜单，每次打开从主页开始。模式／剧本选择页补齐各剧本的真实海岸线缩略图，调整卡片与间距；选择页和四页简报上方增加进入／下一步按钮，底部分页导航继续保留。页面右上角显示界面版本。

## 0.8.1 直接选择模式的主菜单

打开游戏先显示独立主菜单，提供“历史任务、AI 对战、自由沙盘”三个直接入口；主页不显示海图。战场画布和控制组件从初始 HTML 起保持隐藏，只有主动开始任务、进入部署或继续存档时才显示。有存档也不会自动跳过主菜单。

## 0.8 主页与分页任务简报

游戏从主页进入，先选择历史任务、AI 对战或自由沙盘，再选择剧本／预案。任务简报以全屏四页展示战斗简介、剧本细节、部署情况与任务目标；可逐页阅读，也可使用顶部页签切换，最后开始推演。字体、配色与面板沿用战术海图风格。

- 历史任务使用固定兵力，简报只展示友方初始位置与任务区域；敌方位置仍需侦察。AI 对战可在细节页设置双方战术、时限和种子。自由沙盘入口包含现代装备试验场与原有演练。
- 可先进入海图调整可部署剧本的单位与挂载，空白 AI 预案先部署双方再开战。现代试验场与自由沙盘没有强制胜负。
- 战场底部新增“主页”和“简报”。浏览入口与简报期间暂停推演；取消新剧本选择后可返回当前战局。主页可继续浏览器存档或导入 JSON，切换剧本不会自动覆盖存档。
- 入口与分页逻辑位于 `dist/scenario-flow.js`，独立样式位于 `dist/scenario-flow.css`；简报海图直接使用现有游戏海岸线与坐标。

## 0.7 自定义挂载与对海任务

在部署阶段选择现代武装飞机、舰艇或潜艇，在单位面板打开“自定义挂载／自定义弹库”，为该单位命名方案、选择任务并逐类调整弹药。对海任务使用反舰导弹；对陆巡航弹与精确对地弹药不能攻击移动舰船。支持反舰武器的机型另有对海预设，可按反舰火力与自卫弹药的需要选择。专职预警、加油等无武装飞机不开放武器编辑，未装备反舰弹的型号也不能通过编辑获得该武器。

- 自定义数量必须是非负整数，受本型号武器上限、飞机共享载荷及舰艇共享垂发容量约束。短程防空弹按型号的四联装规则折算垂发格，固定反舰发射架、舰炮和独立鱼雷库分别计算。编辑器显示已用额度，超额方案不能应用。
- 选择任务后至少保留该任务所需的武器，例如对海挂载须有反舰弹、反潜须有鱼雷。隐身机是否外挂由实际弹药和内置容量计算，不能自行取消外挂带来的可探测特征变化。
- 自定义方案仅改变当前单位，不修改公共型号库。部署时立即配弹；开战后只有飞机在整备期间可更改下一架次挂载，整备完成前不会增加弹药。舰艇开战后不能换装，AI 接管时手动编辑锁定。
- 航空舰可在部署时为机库各机型指定预设或自定义出动挂载；手动推演中也可调整己方航空舰后续出动计划，不会更改已在空飞机的弹药。手动放飞和双方 AI 均执行已配置方案，继续遵守甲板适配、库存、在空容量及放飞间隔。清除指定方案后恢复自动任务选择，AI 接管期间不能手动改计划。
- 飞机任务弹药耗尽后，AI 按所选任务返航；自定义对海飞机保留自卫空空弹时也会返航重装反舰弹。整备仍消耗有限基地／母舰库存，无法在空中补弹。

v7 存档保存每个单位的自定义方案与舰载机出动方案，导入会重新校验类型、弹药、任务、载荷和垂发容量。AI 战局的初始快照、续跑及同编组重赛保留这些配置；兼容 v1–v6，已有 250／500 公里战局保留原始距离。

## 0.6.1 美中 250 公里对战

“AI 对战”的海空编队、航母航空、反潜搜索与空白预案现在使用虚构的 440 × 260 海里训练海域：蓝方为美方，红方为中方，各有 600 部署点。三个完整预案按各自国家配置舰艇、战机、预警／加油及反潜力量，舰载航空队也遵守所属国家；双方机型与能力不同，仍使用同一套探测、库存、火控和损伤规则。

完整预案中最近的一对前沿单位相距 **250 公里（约 135 海里）**，其余初始单位位于各自后方。自定义部署按阵营筛选，分别限制在两条前沿部署线外侧，确保开战前最近间距至少 250 公里；通用岸基阵地与机场保留为双方可用的抽象单位。空白预案须自行部署双方战斗兵力。战报记录实际开战间距，默认推演时限为两小时。

250 公里表示开始搜索时的双方距离，并不扩大全部导弹射程或保证立即交火；编队需要前出、建立有效航迹，并进入各武器和传感器允许的范围。预警、电子战、空中加油、甲板出动与后勤仍受原有资源限制。这是虚构游戏场景，参数和结果不用于预测现实国家战争。三个历史任务继续使用真实海岸线与原有年代兵力。

v6 存档保存扩展海图、阵营与开战间距。此前的 500 公里美中战局仍保留原海图、阵位与开战间距，可继续推演和重赛；兼容 v1–v5，旧版 AI 对战仍在原 240 × 170 海里地图续跑，不会改动原部署位置。

## 0.5 AI 自动对战平台

打开底部或剧本组件的“AI 对战”，载入海空编队、航母航空、反潜搜索或空白预案；也可以在现代试验场／自由沙盘部署阶段选择“使用当前双方部署”。双方分别部署、撤回单位和配置任务挂载，完成后点击“开始 AI 对战”。原有手动模式和三个历史任务继续使用原先的指挥流程。

- 双方各 600 点，预案包含现代编队，剩余点可按所在沙盘规则配置。可分别选均衡协同、积极进攻或谨慎防御；设置 5–240 分钟时限和 0–4294967295 随机种子。自动对战使用固定一秒步长，相同部署、种子与风格产生可重复的结果，暂停与倍速只改变观看进度。
- AI 每八秒指挥一次，自动开启适用传感器、搜索、绕岛、接敌、发射和防御。规划只读取本方单位、公开海岸与本方可使用的有效航迹。深潜数据链限制照常生效；潜艇按通信窗口或本艇声呐观测升至潜望镜深度。失联目标没有隐藏位置更新。
- 制空机拦截，攻击机按适用武器射程接敌；保留防空弹不计入可用进攻射程，半主动武器的接敌距离受本平台照射视距限制。预警、加油、航空舰与补给平台在本方后方支援，电子战机启用干扰。反潜机低空搜索，直升机交替转场与低速吊放搜索，潜艇低速航行。
- 航母及护航舰双方均自动放飞有限机库中的飞机，依航迹选择制空、反舰、反潜等任务。任务弹药耗尽会返航整备；飞机低油可与兼容加油机会合，否则遵循返航规则。航空补给舰会寻找缺货航空舰并低速转移库存。损失、甲板准备、接口、航油、弹药及库存均受原有规则限制。
- AI 接管后单机手动指令锁定；仍可暂停、使用 1/10/30/120×、选择双方单位看 AI 当前任务及保存／载入。全局观察只影响绘制，不更改 AI 航迹；蓝／红视角各显示本方平台及本方接触。
- 一方战斗平台全部损失后等待在途攻击结算；双方无可用攻击弹药或后续架次则提前结算，达到时限必定结束。时限／主动结束按实际有效毁伤点比较：实际损伤 ÷ 平台完整结构 × 部署点，差值小于 0.5 点为平局。未命中的在途武器不计为预期伤害。
- 战报统计双方投入单位（含已放飞飞机）、现存与损失、武器发射（含近防批次）、命中损伤、成功拦截、航空出动与毁伤评分；可导出 JSON。事件保留最近 400 项，界面显示最近 60 项。“同编组重赛”恢复开战前部署、弹药、损伤、挂载、库存与配置，允许再调整后启动。
- v5 存档保留 AI 计划、配置、统计、时间线、时间步余量和初始部署快照；载入默认暂停并可续跑。兼容 v1–v4 战局，旧战局不会自动启用双方 AI。自动对战属于浏览器内的确定性规则模拟，无需外部 AI 服务，不是定时任务。

核心指挥、战报与配置校验在 `dist/auto-commander.js`，引擎负责既有传感器、物理交战及库存。界面在 `dist/auto-battle-ui.js`。此版本仍是游戏战术抽象，不代表真实国家交战计划。

- 本地战局保存和 JSON 导入／导出；自动迁移 v1 的飞机弹药与在途武器。载入保留失联位置和探测时间，不重新扫描恢复目标。

## 操作

1. 历史任务先查看简报，开始后点击任务指令；在自由部署剧本打开舰队组件，按国家、任务或技术阶段筛选（通用岸基单位位于“通用／历史任务型”系列），再点击海图放置。预设剧本蓝方在 X ≤ 115 海里部署，岸基单位放在西岸；自由沙盘支持双方。
2. 开启雷达或声呐，等待接触从“正在确认”变为“有效航迹”。预警机默认开雷达，能将远方接触共享给开启数据链的友军。
3. 右键设置航点，Shift + 右键追加；也可使用按钮或坐标。飞机可调整高度，低空降低雷达视距；反潜直升机使用吊放声呐时保持低空且 ≤ 40 kn。
4. 选择蓝方平台，再选择红方接触。武器行显示发射条件和阻止发射的原因。可开启单机或全队自动交战，并选择区域防空保留弹药。
5. 留意燃油，提前返航可以加油装弹。部署基地每次补给消耗 ceil(机型部署点 / 4) 点，至少两点；基地共有 30 点。未部署基地时使用后方补给区，每架飞机最多补给两次。
6. 空格暂停／继续，Esc 取消指令；滚轮缩放、拖动平移。底部控制台收放组件，拖动顶栏移动组件；组件收放不影响海图尺寸。
7. “剧本 → 作战机制与平衡”解释探测、制导、资源与单位分工。保存只写浏览器 localStorage，可导出 JSON 跨浏览器迁移。

## 模型与参数边界

坐标为海里，速度为节；移动距离 = 速度 × 推演秒数 / 3600。传感器每三秒更新；单雷达接触通常连续九秒、声呐十二秒确认，多源可加速确认；目视立即确认。六秒未更新后禁止依照该航迹发射，九十秒后删除。电子支援只给粗略位置，但可支持反辐射攻击。

雷达地平线按 2.23 × (√观察高度 + √目标高度) 海里近似；高度以米计。实际雷达范围取地平线、标称范围、天气、损伤、干扰与目标特征折减的较小值。海图橙色虚线圈表示对海几何视距，绿色圈为中空目标的探测上限；不是全圈保证探测。

主动武器在自身导引头范围外只能使用有效航迹，失联沿最后位置飞行；半主动防空弹依赖发射平台持续雷达照射。超音速反舰弹速度更高、威力更强，但成本更高、弹药少、发射较慢。防空、近防、诱饵、燃油和补给库存都有限。命中和拦截使用可保存的确定性随机种子，武器以最多一秒子步长推演，防止高倍率穿越目标。

此模型增加了作战约束，仍是游戏抽象：真实型号仅记录公开定位，未建完整实装数据库；没有 3D、多人联机、逐弹道气动、完整雷达信号处理或舰载机甲板调度。高度切换、起降、声呐浮标与补给过程经过简化；海图不含山地高程。全部战局在浏览器运行。
